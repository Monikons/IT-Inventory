# Учёт оборудования компьютерных классов колледжа

## Назначение проекта

В колледже теряется информация об оборудовании компьютерных классов,
потому что учёт ведут в бумажном журнале и нескольких разрозненных
таблицах. Когда монитор переносят в другой кабинет или принтер уходит
в ремонт, запись не обновляют. Перед проверкой лаборанты по несколько
дней выясняют, что и где стоит, а списанная техника остаётся в списках
как рабочая.

**Цель продукта** — консольное приложение на Python, где у каждой единицы
техники есть карточка, а найти её можно за несколько секунд. Данные
хранятся в файле JSON.

**Пользователи:** лаборант (ведёт учёт), преподаватель (проверяет
оснащение кабинета), завхоз (следит за ремонтом и списанием).

## Запуск

```bash
python main.py
```

Требуется **Python 3.11 или новее** (проверено на 3.12).

Рекомендуется виртуальное окружение:

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

## Запуск тестов

```bash
python -m pytest tests/ -v
```

## Пользовательские сценарии

### Сценарий 1. Лаборант добавляет новое оборудование

**Когда:** в кабинет привезли новый монитор и его нужно поставить на учёт.

1. Запустить программу командой `python main.py`.
2. Выбрать пункт `2 — Добавить оборудование`.
3. Программа покажет номер, который будет присвоен, например `INV-0008`.
   Номер вводить не нужно — он выдаётся автоматически и никогда
   не повторяется.
4. Заполнить обязательные поля: тип, наименование, кабинет, состояние.
   Дату поступления и ответственного можно пропустить — тогда
   в карточке будет «неизвестно».
5. Нажать Enter. Появится сообщение «Запись добавлена. Присвоен номер INV-0008».

**Ошибка.** Если в обязательном поле ничего не ввести, запись
не создаётся и выводится понятное сообщение. Если состояние введено
не из списка, программа попросит повторить ввод.

### Сценарий 2. Преподаватель проверяет оснащение кабинета перед занятием

**Когда:** преподаватель пришёл в кабинет 101 и хочет проверить,
что техника на месте.

1. Выбрать пункт `4 — Показать кабинет`.
2. Ввести номер кабинета `101`.
3. Программа выводит таблицу всех единиц оборудования этого кабинета
   с состоянием каждой.

**Ошибка.** Если в кабинете ничего не числится, будет сообщение
«В кабинете 101 нет оборудования».

### Сценарий 3. Лаборант быстро узнаёт, где стоит техника

**Когда:** сломался компьютер, и нужно понять, в каком кабинете
он находится.

1. Выбрать пункт `3 — Найти по инв. номеру`.
2. Ввести номер, например `INV-0003`. Регистр букв не важен:
   `inv-0003` тоже найдётся.
3. Показана карточка с кабинетом, состоянием и ответственным.

**Ошибка.** Если номера нет, выводится «Не найдено».

### Сценарий 4. Завхоз отправляет оборудование в ремонт или списывает

**Когда:** принтер сломался и уходит в ремонт.

1. Выбрать пункт `5 — Изменить запись`.
2. Ввести номер принтера — программа покажет его карточку.
3. Ввести новое состояние «требует ремонта»; кабинет оставить пустым,
   если он не меняется.
4. Новое состояние сразу видно в списке.

**Ошибка.** Состояние можно ввести только из списка «исправно /
требует ремонта / списано», в любом регистре. Если ни одно поле
не заполнено, выводится «Ничего не изменено».

### Сценарий 5. Лаборант удаляет ошибочную запись

**Когда:** запись создана по ошибке и мешает учёту.

1. Выбрать пункт `6 — Удалить запись`.
2. Ввести номер — программа покажет карточку того, что будет удалено.
3. Ответить `да`. Удаление выполняют только ответы «да», «д», «yes», «y».
   Любой другой ответ, включая пустой, отменяет удаление.

### Сценарий 6. Данные сохраняются между запусками

**Когда:** лаборант закрыл программу и вечером открыл снова.

1. Внести любое изменение (добавить, изменить, удалить запись).
2. Закрыть программу пунктом `0 — Выход`.
3. Запустить программу снова — все изменения на месте.

Сохранять отдельной кнопкой ничего не нужно: изменения записываются
в файл сразу после каждой операции.

### Сценарий 7. Первый запуск на новом компьютере

**Когда:** программу установили на чистый компьютер, где ещё нет
файла данных.

1. Запустить программу — она покажет сообщение «Файл данных ещё
   не создан — программа начнёт с пустого списка».
2. Добавить первую запись — файл `data/inventory.json` создастся сам.

### Сценарий 8. Что делать, если файл данных повреждён

**Когда:** лаборант открыл файл вручную и случайно его испортил.

1. При запуске программа сообщит: «Файл данных повреждён: … Исходный
   файл сохранён как «inventory.json.corrupt-ГГГГММДД-ЧЧММСС»».
2. Данные не потеряны: испорченный файл сохранён рядом с основным
   под другим именем, туда можно заглянуть или передать разработчику.
3. Программа продолжит работу с пустого списка — после исправления
   файла данные вернутся.

### Сценарий 9. Завхоз смотрит оборудование, требующее ремонта

**Когда:** нужно быстро собрать список техники «требует ремонта».

1. Выбрать пункт `7 — Показать по состоянию`.
2. Ввести `требует ремонта` (регистр не важен).
3. Программа выводит таблицу подходящих записей.

## Возможности

| Пункт | Действие |
|-------|----------|
| 1 | Показать всё оборудование (таблица с цветовой индикацией состояния) |
| 2 | Добавить новое оборудование (автоматический номер INV-…, валидация обязательных полей; пропущенные необязательные поля → «неизвестно») |
| 3 | Найти по инвентарному номеру (карточка записи, регистр не важен) |
| 4 | Показать оборудование кабинета |
| 5 | Изменить состояние / кабинет записи |
| 6 | Удалить запись (с подтверждением) |
| 7 | Показать оборудование по состоянию (исправно / требует ремонта / списано) |
| 0 | Выход (данные сохраняются автоматически после каждого изменения) |

## Карточка оборудования

Обязательные поля: уникальный инвентарный номер, тип (ПК, монитор,
принтер и др.), наименование, кабинет, состояние (исправно /
требует ремонта / списано). Дополнительно: дата поступления,
ответственное лицо.

## Хранение данных

Данные лежат в `data/inventory.json`. Формат версии 2:

```json
{
  "version": 2,
  "last_number": 7,
  "items": [
    {
      "inv_number": "INV-0001",
      "equipment_type": "ПК",
      "name": "Dell OptiPlex 3080",
      "room": "101",
      "status": "исправно",
      "date_added": "2024-09-01",
      "responsible": "Иванова А.П."
    }
  ]
}
```

`last_number` — наибольший инвентарный номер, который когда-либо был
выдан. Следующая запись получает `last_number + 1`, поэтому номера не
повторяются даже после удаления последней записи.

Поведение программы:

| Ситуация | Поведение |
|----------|-----------|
| Обычный запуск | Файл читается при старте, данные доступны в меню |
| Первый запуск (файла нет) | Пустой список, без ошибки; файл создаётся при первом изменении |
| Пустой файл | Пустой список, без ошибки |
| Повреждённый JSON | Рядом создаётся копия `inventory.json.corrupt-ГГГГММДД-ЧЧММСС`, работа продолжается с пустым списком; исходные данные не теряются |
| Файл старого формата (список) | Читается без ошибок и при первом сохранении переводится в версию 2 |
| Ошибка записи | Изменение отменяется, пользователь видит сообщение; файл остаётся прежним |

Запись выполняется атомарно: данные сначала пишутся во временный файл,
затем подменяют основной через `os.replace`, поэтому сбой не оставляет
недописанный JSON.

## Запуск в Docker

Сборка и запуск (если Docker установлен):

```bash
docker build -t it-inventory .
docker run --rm -it -v "${PWD}/data:/app/data" it-inventory
```

Папка `data` монтируется снаружи, чтобы файл `inventory.json` сохранялся
между запусками контейнера. Без монтирования данные пропадут после
удаления контейнера.

Проверка тестов внутри образа:

```bash
docker run --rm it-inventory python -m pytest tests -q
```

Образ собирается на базе `python:3.12-slim`. На учебных машинах без Docker
достаточно обычного запуска через Python.

## Границы проекта и известные ограничения

**В рамках:** просмотр, добавление, поиск, изменение, удаление,
фильтрация по кабинету и состоянию, сохранение в JSON, устойчивость
к отсутствию/повреждению файла, автотесты, Docker-черновик.

**Вне рамок / известные ограничения:**

- графический интерфейс;
- база данных и многопользовательский доступ с ролями;
- учётные записи пользователей;
- печать отчётов и экспорт в Excel/CSV;
- история изменений (кто и когда менял запись);
- произвольные состояния сверх трёх фиксированных;
- Docker не является обязательным для сдачи (работает обычный Python).
