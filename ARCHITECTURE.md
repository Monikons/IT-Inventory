# Архитектура

Приложение состоит из двух модулей и одного файла данных.

```
main.py  ──►  inventory.py  ──►  data/inventory.json
(меню, ввод/вывод)  (модель, логика, хранение)  (формат версии 2)
```

## Модули

| Файл | Ответственность |
|------|-----------------|
| `main.py` | Консольный интерфейс: меню, таблицы и карточки, цвета, запросы ввода. Не содержит правил учёта — только вызывает `Inventory` и показывает результат. |
| `inventory.py` | Модель карточки, проверка данных, нумерация, операции над записями, чтение и запись JSON. Ничего не печатает и не читает с клавиатуры. |
| `data/inventory.json` | Данные. Формат: `{"version": 2, "last_number": N, "items": [...]}`. |
| `tests/` | Автотесты pytest и скрипт ручной проверки `qa_manual_check.py`. |

## Ключевые функции `inventory.py`

**Чистые функции** (без файлов и ввода-вывода, проверяются тестами напрямую):

- `parse_inv_number`, `format_inv_number` — перевод между `INV-0007` и числом 7.
- `next_inv_number(items)` — следующий номер по списку записей.
- `normalize_item` — обрезает пробелы, приводит состояние к нижнему регистру, пустые необязательные поля заменяет на «неизвестно».
- `validate_item` — проверка пяти обязательных полей и допустимого состояния.
- `display_value` — что показать пользователю вместо пустого значения.

**Класс `Inventory`** (хранит список записей и счётчик `last_number`):

| Метод | Что делает |
|-------|-----------|
| `load()` | Читает файл. Нет файла, пустой файл, повреждённый JSON, старый формат (список) — каждый случай обработан, программа не падает. Сообщение для пользователя — в `load_message`. |
| `save()` | Атомарная запись: во временный файл, затем `os.replace`. |
| `create(fields)` | Добавляет запись с автоматическим номером `last_number + 1`. |
| `add(item)` | Добавляет запись с готовым номером; проверяет поля и уникальность. |
| `find(number)` | Поиск без учёта регистра и пробелов. |
| `update(number, status=, room=)` | Меняет состояние и/или кабинет. |
| `delete(number)` | Удаляет запись. |
| `by_room(room)`, `by_status(status)` | Фильтры по кабинету и состоянию. |

Операции возвращают пару `(успех, сообщение)`, поэтому интерфейс и тесты работают с ними одинаково.

## Как защищены данные

1. **Автосохранение.** После каждого добавления, изменения и удаления вызывается `_commit`.
2. **Откат при ошибке записи.** Перед изменением делается снимок списка и счётчика; если запись на диск не удалась, снимок возвращается, пользователь видит сообщение, файл остаётся прежним.
3. **Атомарность.** Недописанный JSON не появляется: основной файл подменяется только после успешной записи временного.
4. **Повреждённый файл не теряется.** Рядом сохраняется копия `inventory.json.corrupt-ГГГГММДД-ЧЧММСС`; если такая же копия уже есть, новая не создаётся.
5. **Номера не повторяются.** `last_number` хранится в файле и не уменьшается при удалении.

## Почему так

Правила учёта отделены от экрана: логику проверяют автотесты без клавиатуры (`monkeypatch` подменяет ввод только в тестах интерфейса), а интерфейс можно заменить, не трогая данные. Хранение в одном JSON-файле выбрано как достаточное для учебного объёма и требований проекта; база данных вне рамок.
