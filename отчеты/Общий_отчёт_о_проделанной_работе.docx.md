## **1\. Цель и результат**

Цель: разработать консольное приложение на Python для учёта компьютерного оборудования с хранением в JSON, автотестами и документацией; работа в команде из трёх человек с ротацией ролей PO, LD и QA / DevOps.

## **4\. Технические решения**

* Два модуля: main.py отвечает за экран и ввод, inventory.py — за правила учёта и хранение. В inventory.py ничего не печатается и не читается с клавиатуры, поэтому логику проверяют тесты напрямую.  
* Автоматические номера: номер \= last\_number \+ 1, счётчик хранится в файле и не уменьшается при удалении, поэтому номер удалённой записи не повторяется.  
* Формат данных версии 2 (version, last\_number, items); файл старого формата читается и при сохранении переводится в новый.  
* Безопасная запись: временный файл и os.replace; при ошибке записи изменение откатывается, интерфейс не сообщает «сохранено».  
* Повреждённый JSON: сообщение пользователю и резервная копия inventory.json.corrupt-…; одинаковые повреждённые файлы не плодят копии (DEF-07).  
* Отличие от рекомендованной структуры плана: нет отдельного storage.py, хранение внутри класса Inventory. Решение нужно объяснить на защите.

## **7\. Ограничения и риски**

* Docker: клиент есть, демон не запущен, образ не собирался. Dockerfile остаётся дополнительным результатом и не блокирует сдачу.  
* pip install \-r requirements.txt и Python 3.11 / 3.12 не проверялись, прогон был на 3.13.  
* Приложение однопользовательское, данные в одном файле; известные ограничения перечислены в USER\_GUIDE.md.
