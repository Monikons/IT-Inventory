Полное описание — в ARCHITECTURE.md. Коротко: main.py отвечает за экран и ввод, inventory.py — за правила учёта и хранение, data/inventory.json — данные формата версии 2\.

| Что показать | Где | Смысл |
| :---- | :---- | :---- |

## **Проверка репозитория перед сдачей**

В присланном архиве нет папки .git, поэтому состояние Git проверить по архиву нельзя. Перед сдачей это делается на компьютере, где лежит рабочий репозиторий:

| Проверка | Команда | Ожидаемый результат |
| :---- | :---- | :---- |
| Рабочее дерево чистое | git status | nothing to commit, working tree clean |
| Основная ветка | git branch | В main — рабочая версия, ветки задач объединены |
| Осмысленные коммиты | git log \--oneline | Сообщения вида «Добавлен поиск по кабинету», не «готово» |
| Вклад каждого участника | git shortlog \-sn | Есть коммиты у всех троих |
| Нет лишних файлов | git ls-files | Нет .venv, .idea, \_\_pycache\_\_, \*.corrupt-\* |
| Удалённый репозиторий | git remote \-v | Ссылка для сдачи (или архив вместе с .git) |

## **Замечания по структуре**

* Рекомендованная структура плана включает отдельный модуль storage.py. В проекте чтение и запись JSON находятся внутри класса Inventory (inventory.py): модулей два, а не три. Это допустимо (структура рекомендована, не обязательна), но на защите стоит объяснить решение: хранение тесно связано с счётчиком last\_number и откатом при ошибке записи, поэтому вынесено не было.  
* Dockerfile ставит pytest напрямую командой pip install, а не из requirements.txt. Работает, но при добавлении зависимостей файлы придётся менять в двух местах.  
* Docker-образ не собирался (нет запущенного демона), поэтому Dockerfile остаётся черновиком. Основной способ запуска — python main.py.
