2. ## **Что реализовано в inventory.py**

| Метод | US | Что делает | Контракт |
| :---- | :---- | :---- | :---- |
| find(inv\_number) | US-3 | Поиск по точному номеру | dict \\\| None |
| by\_room(room) | US-4 | Все записи кабинета | list\[dict\] |
| update(inv\_number, \*\*changes) | US-5 | Меняет status (с валидацией) и/или room | (bool, str) |
| delete(inv\_number) | US-6 | Удаляет запись | (bool, str) |

**Мои технические решения:**

* Все мутирующие методы возвращают (ok, msg) — единый контракт для тестов QA. При отсутствии записи msg \== "Не найдено".

* update() валидирует status по VALID\_STATUSES; пустой room игнорируется.

* delete() сначала вызывает find(), потом remove() — без найденной записи удаления нет.

* by\_room() — точное совпадение строки кабинета.

## **Что реализовано в main.py**

| Пункт | Действие | Поведение |
| :---- | :---- | :---- |
| 3 | action\_find | Пустой ввод → предупреждение; найден → карточка; нет → «Не найдено.» |
| 4 | action\_room | Пустой ввод → предупреждение; есть записи → таблица; нет → «В кабинете N нет оборудования.» |
| 5 | action\_update | Показывает карточку, спрашивает новое состояние/кабинет; пустые поля \= не менять; «Ничего не изменено» |
| 6 | action\_delete | Показывает карточку, требует подтверждение (да/д/yes/y); отмена → «Удаление отменено. Запись осталась.» |

Пустой ввод и отсутствующая запись не приводят к аварийному завершению.
