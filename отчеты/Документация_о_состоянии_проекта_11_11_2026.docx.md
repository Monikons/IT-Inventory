**ДОКУМЕНТАЦИЯ О СОСТОЯНИИ ПРОЕКТА**

**на 11 ноября 2026 года**

**1\. Общая информация о проекте**

Проект представляет собой консольное приложение на Python для учёта оборудования компьютерных классов колледжа. Основная задача системы — обеспечить хранение и актуализацию информации об оборудовании, включая его инвентарный номер, тип, наименование, кабинет и текущее состояние.

**2\. Текущее состояние проекта**

По состоянию на 11.11.2026 завершены работы, запланированные в рамках первого и второго дней разработки. Сформирована базовая структура приложения, подготовлены требования и User Stories, реализован просмотр и добавление оборудования, а также выполнена проверка основного функционала.

**3\. Реализованный функционал**

* запуск консольного приложения через основной файл программы;  
* отображение списка оборудования;  
* вывод основных данных каждой единицы оборудования;  
* добавление нового оборудования;  
* проверка заполнения обязательных полей;  
* проверка уникальности инвентарного номера;  
* обработка некорректного пользовательского ввода без аварийного завершения программы;  
* автоматическое тестирование основных сценариев добавления оборудования.

**4\. Подготовленная документация**

* описание ситуации заказчика и назначения проекта;  
* User Stories с критериями приёмки;  
* описание задач, выполненных командой в рамках первых двух этапов работы;  
* демонстрационные данные оборудования;  
* примеры корректных и ошибочных входных данных;  
* протоколы проверки реализованного функционала.

**5\. Тестирование и контроль качества**

Для проверки функциональности были добавлены автоматические тесты. Проверяются успешное добавление оборудования, обработка пустых обязательных полей и предотвращение создания записей с повторяющимся инвентарным номером. Также проведена проверка устойчивости программы к некорректному вводу данных.

**6\. Работа с репозиторием**

Изменения в проекте проходили проверку через отдельную ветку разработки и после проверки объединялись с основной веткой. Участники команды выполняли коммиты своих частей работы, что позволяет отслеживать ход разработки и распределение задач.

**7\. Состояние на начало следующего рабочего дня**

На начало 11.11.2026 базовый функционал просмотра и добавления оборудования считается подготовленным. Проект готов к дальнейшему расширению функциональности.

**8\. Рекомендуемые задачи на 11.11.2026**

* реализовать поиск оборудования по инвентарному номеру;  
* реализовать поиск или вывод оборудования по номеру кабинета;  
* добавить возможность изменения кабинета или состояния оборудования;  
* реализовать удаление ошибочных записей с подтверждением действия;  
* продолжить расширение набора автоматических тестов;  
* проверить работу нового функционала перед объединением изменений с основной веткой.

**9\. Текущие риски и замечания**

* необходимо сохранять единые правила валидации данных в основной логике приложения, чтобы интерфейс и тесты использовали одинаковые проверки;  
* при добавлении нового функционала требуется сохранять устойчивость программы к пустому и некорректному вводу;  
* изменения рекомендуется предварительно проверять в отдельной ветке перед объединением с основной версией проекта.

**10\. Итог**

Проект находится на этапе активной разработки. Основная структура приложения сформирована, базовые операции с оборудованием частично реализованы и протестированы. На следующем этапе необходимо расширить функциональность работы с записями оборудования и продолжить автоматическое тестирование.
