# User Stories и критерии приёмки

| ID | Приоритет | Спринт | User Story | Критерии приёмки | Статус приёмки (спринт 5) |
|----|-----------|--------|------------|------------------|---------------------------|
| US-1 | Must | 1 | Как лаборант, я хочу видеть список всего оборудования, чтобы понимать, что у нас есть. | 1) Пункт меню «Показать оборудование» выводит не менее 5 записей. 2) У каждой видны номер, тип, наименование, кабинет, состояние. 3) При пустом списке показано «Список пуст». | **Принято** — таблица выводит все поля, пустой список обрабатывается. |
| US-2 | Must | 2 | Как лаборант, я хочу добавлять новое оборудование, чтобы список был актуальным. | 1) При вводе всех 5 обязательных полей запись появляется в списке. 2) Пустое поле — понятная ошибка, запись не создаётся. 3) Уже существующий инвентарный номер не принимается. 4) Программа не завершается аварийно. 5) Инвентарный номер присваивается автоматически (INV-0001, INV-0002 …) и никогда не выдаётся повторно, даже после удаления записи. 6) Необязательные поля (дата поступления, ответственный), если их пропустили, показываются как «неизвестно». | **Принято** — автонумерация и last_number, «неизвестно» работают. |
| US-3 | Must | 3 | Как лаборант, я хочу находить компьютер по инвентарному номеру, чтобы быстро узнать, в каком кабинете он находится. | 1) По существующему номеру показывается карточка. 2) По неизвестному — сообщение «Не найдено». 3) Пустой ввод не приводит к аварии. 4) Номер находится независимо от регистра: inv-0001 и INV-0001 — одна запись. | **Принято** — регистронезависимый поиск, DEF-01 закрыт. |
| US-4 | Should | 3 | Как преподаватель, я хочу видеть всё оборудование кабинета, чтобы проверить его наличие перед занятием. | 1) По номеру кабинета выводятся все его записи. 2) Если записей нет — сообщение «В кабинете нет оборудования». 3) Пустой ввод обрабатывается без аварии. | **Принято**. |
| US-5 | Must | 3 | Как лаборант, я хочу менять состояние или кабинет записи, чтобы данные отражали ремонт и перенос техники. | 1) Допустимы только состояния «исправно», «требует ремонта», «списано»; регистр и лишние пробелы не важны. 2) Неизвестный номер — «Не найдено». 3) Новое значение видно в списке сразу после изменения. | **Принято** — DEF-02, DEF-03, DEF-04 закрыты. |
| US-6 | Must | 3 | Как лаборант, я хочу удалять ошибочные записи, чтобы список не засорялся. | 1) Перед удалением программа просит подтверждение. 2) При отмене запись остаётся. 3) Неизвестный номер — «Не найдено», без аварии. 4) Удаляют только ответы «да», «д», «yes», «y»; любой другой ответ, включая пустой, отменяет удаление. | **Принято**. |
| US-7 | Must | 4 | Как лаборант, я хочу, чтобы данные сохранялись после закрытия программы, чтобы не вводить их заново. | 1) После перезапуска записи на месте. 2) Если файла нет — старт с пустым списком без сбоя. 3) Повреждённый JSON даёт сообщение и не стирает данные молча. 4) Запись с отсутствующими полями в файле не приводит к аварийному завершению программы. 5) Пустой файл (0 байт) — пустой список без сбоя. 6) Повторный запуск после добавления, изменения и удаления показывает последние данные. | **Принято** — все 6 критериев подтверждены автотестами и ручными проверками спринта 4–5. |
| US-8 | Should | 5 | Как завхоз, я хочу видеть список оборудования по состоянию, чтобы планировать ремонт и списание. | 1) По выбранному состоянию выводятся соответствующие записи. 2) Регистр и пробелы не важны. 3) Если записей нет — понятное сообщение. 4) Пустой ввод не приводит к аварии. | **Принято** — пункт меню 7, метод by_status, тесты. |

## Согласованный формат хранения (решение PO, спринт 4)

**Файл:** `data/inventory.json`, кодировка UTF-8, отступ 2 пробела.  
**Формат:** версия 2.

```json
{
  "version": 2,
  "last_number": 7,
  "items": [ { "inv_number": "INV-0001", "equipment_type": "ПК", ... } ]
}
```

| Поле | Назначение |
|------|-----------|
| `version` | Номер формата. Позволяет отличить старый файл от нового и не ломать данные при смене структуры. |
| `last_number` | Наибольший выданный инвентарный номер. Следующая запись получает `last_number + 1`. |
| `items` | Список карточек оборудования. Поля карточки не изменились. |

**Файл старого формата** (обычный JSON-список записей) продолжает читаться и при первом сохранении сам переводится в версию 2. Существующие пользователи ничего не теряют.

## Поведение при первом запуске и при проблемах с файлом (решение PO)

| Ситуация | Требование PO |
|----------|---------------|
| Файла нет (первый запуск) | Пустой список, без ошибки. Файл создаётся при первом изменении. Лаборант видит сообщение, что файл ещё не создан. |
| Файл пустой | Пустой список, без ошибки, с понятным сообщением. |
| JSON повреждён | Сообщение о повреждении, рядом создаётся резервная копия `inventory.json.corrupt-…`. Данные не теряются молча. |
| Файл старого формата | Читается без ошибок, переводится в версию 2 при сохранении. |
| Ошибка записи на диск | Изменение отменяется, пользователь видит сообщение об ошибке. Интерфейс не показывает «сохранено», если на диск ничего не записалось. |
| Сохранение после изменений | Отдельной кнопки «Сохранить» нет: файл записывается сразу после добавления, изменения и удаления. |
