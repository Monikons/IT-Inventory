# Инструкция пользователя

**Программа:** Учёт оборудования компьютерных классов колледжа  
**Версия:** итоговая (спринт 6)  
**Требования:** Python 3.11 или новее

## Быстрый старт

1. Откройте терминал в папке проекта.
2. (По желанию) создайте виртуальное окружение и установите зависимости:
   ```bash
   python -m venv .venv
   source .venv/bin/activate   # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   ```
3. Запустите программу:
   ```bash
   python main.py
   ```
4. Появится меню. Выберите нужный пункт цифрой и нажмите Enter.

Данные хранятся в файле `data/inventory.json`. После каждого добавления, изменения или удаления файл обновляется автоматически. Отдельной кнопки «Сохранить» нет.

## Что умеет программа

| Пункт | Действие |
|-------|----------|
| 1 | Показать весь список оборудования (таблица с цветовой индикацией состояния) |
| 2 | Добавить новую запись. Инвентарный номер выдаётся автоматически (INV-0001, INV-0002 …). Необязательные поля (дата, ответственный) можно пропустить — в карточке будет «неизвестно». |
| 3 | Найти запись по инвентарному номеру. Регистр букв не важен (`inv-0003` = `INV-0003`). |
| 4 | Показать всё оборудование выбранного кабинета. |
| 5 | Изменить состояние и/или кабинет существующей записи. |
| 6 | Удалить запись (с подтверждением «да» / «д» / «yes» / «y»). |
| 7 | Показать оборудование с выбранным состоянием (исправно / требует ремонта / списано). |
| 0 | Выход. |

## Карточка оборудования

**Обязательные поля:**  
инвентарный номер, тип (ПК, монитор, принтер …), наименование, кабинет, состояние.

**Состояния:** только «исправно», «требует ремонта», «списано» (регистр и лишние пробелы не важны).

**Дополнительно:** дата поступления, ответственное лицо. Если не указаны — показывается «неизвестно».

## Типичные ситуации

### Первый запуск на новом компьютере
Если файла `data/inventory.json` ещё нет, программа сообщит об этом и начнёт с пустого списка. После первого добавления файл создастся сам.

### Файл данных повреждён
Программа покажет сообщение, сохранит испорченный файл рядом под именем `inventory.json.corrupt-ГГГГММДД-ЧЧММСС` и продолжит работу с пустого списка. Исходные данные не теряются молча. Если тот же файл остался и при следующем запуске, новая копия не создаётся.

### Ошибка записи на диск
Изменение отменяется, пользователь видит сообщение. Файл остаётся в прежнем состоянии.

## Запуск в Docker (если Docker установлен)

```bash
docker build -t it-inventory .
docker run --rm -it -v "${PWD}/data:/app/data" it-inventory
```

Папка `data` монтируется, чтобы данные сохранялись между запусками контейнера.

## Известные ограничения

- Только консольный интерфейс (без графического окна).
- Один файл данных на всю программу; нет разделения по пользователям и ролям.
- Нет печати отчётов и экспорта в Excel/CSV.
- Нет истории изменений (кто и когда менял запись).
- Состояния жёстко заданы тремя значениями; новые статусы требуют правки кода.
- Docker-образ описан в `Dockerfile`, но сборка и запуск в нём не проверялись (в среде проверки не было работающего Docker). Основной способ запуска — обычный Python.
- Требуется Python 3.11+ (проверено на 3.12).

## Куда обращаться при проблемах

Смотрите файл `README.md` (раздел «Хранение данных») и `USER_STORIES.md` (критерии приёмки). При повреждении файла сначала проверьте резервную копию `*.corrupt-*`.
